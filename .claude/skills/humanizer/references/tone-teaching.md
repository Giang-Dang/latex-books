# Tone: Teaching

**Use for:** tutorials, step-by-step guides, onboarding docs, explanations written for someone
meeting the topic for the first time.

**Person and personality level:** `restrained`. "You" for the learner. "We" only when genuinely
walking through something together. No "I" unless the piece is explicitly a personal walkthrough.

**Sentence rhythm:** short, one idea per sentence, one step per paragraph. Rhetorical questions are
allowed but rare, and only where the explanation genuinely changes direction.

**Terminology:** define a term in one clause at first use, then use exactly one name for it
forever. §11 does more damage in this tone than in any other: an expert reads two names as
stylistic variation, a beginner reads them as two different things.

## Tells specific to this tone

- **Difficulty-flattening adverbs.** "simply", "just", "obviously", "of course", "all you have to
  do is". A learner stuck at exactly that step concludes the fault is theirs. Delete the adverb and
  the sentence is both truer and shorter.
- **"As you know"** and "you're probably already familiar with", covering a step that was skipped.
  The reader does not know. That is why they are here.
- **A glossary dump before anything happens** (§16). Introduce each term at the point it is first
  needed.
- **"Congratulations! You've now learned..."** closers.
- **§13 passive in instructions.** "The file will be created." The learner needs to know what to
  type and what appears afterward.

## Before and after

**Before:** Simply run `git init` and the repository will be created. As you know, Git is a
distributed version control system, so of course you'll want to add a remote as well.
Congratulations, you've now set up your first repo!

**After:** Run `git init` in your project folder. It creates the repository there. Git is
distributed, so that history lives only on your machine until you add a remote and push to it.
