**Mosaic is seven services.** `src/Mosaic.Api` does not exist. Catalog owns
`Product` on 5101; Pricing (5102), Inventory (5103) and Reviews (5105) each
contribute fields to it; Accounts (5104) owns `Customer`, which became an entity
at `ch12` because two services reference one; Ordering (5106) owns `Order` and
references `Product` and `Customer` with `resolvable: false` on both. Six
databases on one PostgreSQL container, created by `EnsureCreatedAsync` on first
start. The seventh service, `src/Mosaic.Nodes` on 5107, arrived at `ch13` and is
the only one with no database and no domain: it owns `Query.node` and
`Query.nodes` for the whole graph and declares four two-line stubs to do it.
`src/Mosaic.ServiceDefaults` is the first project in the repo that is not a
service: the request timeline, the two counters, the snake_case convention and
the builder calls that make a subgraph composable. The Cosmo Router in front of
all seven is unchanged from `ch10` and is handed a different execution config.

Getting there: `ch08` extracted Catalog; `ch09` added the composed config as a
committed file and five composition failures on purpose; `ch10` put the router
in front; `ch11` added `Product.shippingCost` with `@requires(fields:
"category")` and `samples/entity-resolution`; `ch12` emptied and deleted the
monolith, added `scripts/override-cases.mjs`, and retired
`mosaic-federation.postman_collection.json` for `mosaic-subgraphs`; `ch13` added
the node service, made `Review` and `Order` entities, fixed a paging cursor
chapter 4 broke, and added `scripts/modeling-cases.mjs` and
`samples/interface-object`; `ch14` added `mosaic-nats`, a NATS publisher inside
Reviews, and an eighth subgraph that is a file.

**The eighth subgraph has no process.** `schema/streams.graphql` declares one
subscription field and the `@edfs__natsSubscribe` directive it uses, and there
is no project, port or process behind it. The router reads the directive,
subscribes to NATS itself, and resolves the payload out of the other seven by
key. It composes to a `PUBSUB` datasource with no fetch url; the `routing_url`
the composer input is obliged to give it is copied into the config's subgraph
list and nothing ever calls it, which is why it points at 5108 where nothing
listens.

**Four of the seven services check tokens.** Chapter 15 gave the graph an
identity: an HS256 token minted by `scripts/mint-token.mjs` whose `sub` is a
customer's global object identifier, validated by the router and again by
Accounts, Reviews, Ordering and Nodes. Four fields are guarded, and the rule is
written twice on each of them, once as a federation directive the router
enforces and once as a `[Authorize]` the service enforces, because all seven
services publish host ports. `Query.node` is guarded in two more places again,
by type at Nodes and by instance in Ordering's reference resolver.

**Three subgraphs revalidate every repeat request, and nobody chose that.**
Chapter 16's headline. `AddMosaicAuthorization()` is `AddAuthorization()` and
nothing else, and besides the two middleware chapter 15 found it registers
`AuthorizeValidationRule`, whose `IsCacheable` is hard-coded false. One
non-cacheable rule makes `DocumentValidator.HasNonCacheableRules` true, and
`DocumentValidationMiddleware` then re-opens validation on every document-cache
hit. So Accounts, Reviews and Ordering re-validate for ever and Catalog,
Pricing, Inventory and Nodes do not - the same three-versus-four split as
decision 95's middleware counts, from the same one line (decision 104).

**The router keys its plan cache on less of your document than you would
guess, and splits it on more.** Chapter 17's headline, and the answer to a
question chapters 7, 10, 11 and 13 each asked in a different form. The key is a
hash of the normalised document with the operation name blanked, so eleven
documents differing in operation name, variable names, argument values,
whitespace and fragment use share one plan; an alias, a change of field order,
or a `!` on a declared variable each buy a second (decision 109). The two
headers that display a query plan take that request off the cache path
entirely, so the planning time in a trace is always the cold number (decision
110). And on the composer's side, an unresolvable key is reported against the
first root field declared rather than every route that fails, which closes what
chapter 9 recorded and could not explain (decision 108).

Next action: chapter 18, the wire completely. It inherits what its Progress row
names, and chapter 17 adds nothing to that row: this chapter stood entirely on
the router-to-subgraph side of the wire and chapter 18 owns the client-to-router
side. Nothing chapters 16 or 17 did changes any service, so the graph chapter 18
walks is still the one chapter 15 left.

**Length, remeasured 2026-08-12.** Decision 10's page ceiling is closed
(decision 105) and this paragraph is now a fact rather than a comparison against
a target. Seventeen chapters drafted put the whole document at 358 pages, of
which chapter content runs to page 296; eleven chapters and five appendices are
still stubs. That is about 17 pages a chapter over the seventeen, the same rate
the halfway measurement found, and chapter 17 is 16.

## Writing rules (book-specific)

Library-wide defaults are in AGENTS.md; these are this book's additions.

- Every hands-on chapter includes a "verify it in Postman" step.
- Internals claims are pinned: name the HotChocolate 16.x source tag or Cosmo
  release a walkthrough was checked against.
- Code listings come from the mosaic-graph companion repo once it exists;
  until then, write no listings that pretend to be real code.
- A chapter that ships code is not drafted until `pwsh scripts/verify.ps1` in
  that repo prints PASS and the chapter's `chNN` tag is pushed. If a chapter
  legitimately changes one of the numbers the script asserts, update the script
  and say so in the commit message; never loosen an assertion to make a run
  pass.
- Whatever is added to one verification script is added to the other in the same
  commit. A second gate that silently checks less is worse than no second gate,
  and `verify.sh` has drifted twice already.
- A number the prose prints has something committed that produces it again.
  Three separate audits found the same defect, in chapter 10's latency table,
  chapter 11's cost table and two of chapter 13's listings, and the act of
  making a measurement reproducible is what finds out whether it was right:
  chapter 11's numbers moved when the harness arrived. Decisions 55, 62 and 66
  are the shape this settled into, including the split between a behaviour,
  which becomes a case both gates run, and a timing, which becomes a committed
  script a reader can run twice.
- A timing is a single-machine number. The ratio is the claim, the milliseconds
  are not, and a before-and-after has to be measured in one sitting: the same
  `ch04-ef` code measured 10-12 ms in one pass and 19-20 ms in another purely
  because the machine was busier. Chapters 03, 04, 07 and 10 all print timings
  on these terms.
- Case scripts normalise line endings on read. `schema export` writes CRLF on
  Windows, every case literal is written with `\n`, and `.gitattributes` puts
  the file back at the next commit, so an unnormalised read fails with "matched
  0 times" and then stops failing.
- A gate that cannot tell "the tool disagrees" from "the tool did not run" will
  send somebody to look at the wrong thing. Empty tool output is retried once
  and then reported as the tool never having reported, which is what
  `modeling-cases.mjs` does after a composer that had run out of memory was
  reported as a disagreement about schemas.
- A number that fixes a fact in time needs a source or it does not go in. Chapter
  14 nearly shipped "deprecated since 2019" about a WebSocket protocol, asserted
  from memory, traceable to nothing, and caught only by the audit. The failure is
  the same family as decision 59's three wrong numbers and is easier to make:
  a year attached to a true claim reads as detail rather than as an assertion,
  and no gate can see it. Either cite it or write the claim without it.
- A surprising measurement gets a control before it gets a sentence. Chapter 15
  produced three wrong explanations in a row from real observations: a
  subscription refusing a guarded field was written up as the router ignoring an
  initial-payload identity, when a second run with the setting removed showed
  the block was refusing every anonymous HTTP request as well; an event that
  failed to deliver was read as an expiry, when the customer identifier in the
  probe was one nobody had seeded; and the guarded-field refusal was attributed
  to the pre-fetch setting until the same run with it off behaved identically.
  Each was found by changing exactly one thing and running it again, and each
  would have been printed otherwise, because the first explanation fitted
  everything that had been seen. A fourth one shipped in the first draft and was
  caught the next day: the same guarded-field refusal was written up as a
  property of subscriptions, on a payload contrast where the two requests
  differed in their selection sets as well as their transports (decision 100).
  The rule: before a measurement becomes a sentence, run the version that should
  behave differently, and make sure the thing you vary is the thing the sentence
  names. The fourth instance also says which observation to trust when two
  disagree: the payload reported on the behaviour and the subgraph's request log
  was the behaviour, and only the count settled it. This is the sibling
  of the rule below rather than a repeat of it: that one is about describing the
  run you actually made, this one is about making the second run.
- Measure the thing the sentence is about. Chapter 14 wrote that the router logs
  nothing about a failed transport at `log_level: debug`, having observed a
  router running at `info`. Re-measured at `debug` there is one line, and it
  names the cause. The near miss is worth a rule because the observation was
  real and only the condition was wrong, which is the shape that survives a
  re-read: check that the run you are describing is the run you made.
- A name is not a source. This is the sibling of the two rules above, for the
  chapters that read a source tree rather than run something. Chapter 16 found
  a struct with a field called `BacklogMaxSize` and wrote down that the operation
  compiler works through an iterative backlog, which reads well, follows from
  the name, and is false at this tag: grepping the core project for the word
  finds it only in schema type-reference resolution, and there is no backlog in
  the compiler at all. The type turned out to be dead code left behind by the
  design that removed the backlog. An identifier is evidence that somebody once
  meant something by it, and nothing more. Read the thing it names, or do not
  write the sentence.
- A step added to both verification scripts is tested against the same captured
  line, not written twice from the same idea. Chapter 16 added one step to each
  and the two patterns disagreed about a single space: the PowerShell regex
  matched `document cache` anywhere and the shell one asked for a space in front
  of it, where the timeline actually writes `(document cache hit`. verify.ps1
  passed and verify.sh reported the listener as missing, which is the exact
  failure mode the parity rule above exists to prevent, arriving through the
  patterns rather than through a missing step. The same run turned up a second
  instance with the same shape: `subgraph_url` in verify.sh had no `nodes` case
  and had not had one since chapter 13, because every caller until now named one
  of the six by hand. Run both scripts before calling a step done.
  This SPEC and the research notes are planning documents rather than the book,
  and chapter 12 twice put an open item's sentence in chapter 10's mouth. No
  gate can catch it: the quotation is well formed and the sentence is true.
- Chapter numbers in prose are `chapter~\ref{ch:...}`, never a literal number.
  Chapters 01 to 11 contain none between them and chapter 12 arrived with ten,
  which is what a chapter that refers back a lot does when nobody is watching.
- A Postman collection is rewritten rather than patched once its URLs have
  outlived two extractions. Measured twice, at `ch08` and at `ch12`; patching
  one was slower than rewriting it both times.
- Each chapter ends with a "Your turn" lab referencing a companion-repo tag.
- Facts from research/2026-08-federation-landscape.md must be re-verified
  before drafting the chapters that use them (Parts VI and VII especially).
- Citations are `~\autocite{...}`, always with the tilde, so a bracketed number
  can never start a line on its own.
- Quoted material uses `\enquote{}` (csquotes), never literal quote characters.
- A figure's `tikzpicture` lives in figures/tikz/ as a bare picture; the
  `figure` environment, caption and label stay at the call site in the section
  file.
- Vendor-published sources are usable only when they quote a named engineer at
  the company being described, and the prose says whose blog it was.
- Numbers we measured ourselves rather than found published must say so in the
  text ("I counted..."), and the research file must record how to reproduce the
  count.
- Voice: first-person practitioner. First person singular, opinionated where
  experience warrants it and willing to concede. No contractions in my own
  voice; they appear only inside quoted material. Sentence length varies, and a
  short declarative sentence lands the end of a paragraph or a section.
  Sections end on a hinge into the next one. Claims are concrete - a company, a
  date, a number, a name - because the vague authority ("experts argue",
  "industry reports") is the failure this voice exists to avoid.
- Economy: tight, which is what `tone-chapter.md` sets and this book keeps. Say
  it once: a point made in the prose is not restated in the section's closing
  paragraph. No setup paragraph before the paragraph that does the work, and no
  section opening that announces what the section covers. One idea per
  paragraph. Every sentence carries a fact, a decision or a consequence.
  Economy is not sentence length and does not touch the Voice line above:
  varied cadence still holds, the short declarative still lands a paragraph,
  and a run of uniform short sentences is still a tell. Labs and appendices run
  tight for their own reasons; see decision 114. This governs prose written from
  here on. Chapters 01 to 17 were drafted before it and are not retro-fitted,
  so chapter 18 is the first one this line binds.
- Humanizer skill: humanizer. The book is in English, so a draft is judged
  against the English tone profiles, not the humanizer-vi ones.
- Spelling is British-leaning: organisation, centre, labelled, initialisation.
  Product and API names keep whatever spelling their vendor chose, so
  HotChocolate ships Types.Analyzers and its analyzers stay analyzers. The
  enforced variety and the four exemptions are in check-chapter.psd1; this is
  the rule they enforce.
- Listings are drawn from the environments decisions 23 and 38 name, and each
  one exists as a `\newminted` alias or a stock lexer in preamble/packages.tex.
  Adding an environment is a decision, recorded in the log.
- Every file in this book is ASCII, with one exception: a `minted:text` listing
  may carry a non-ASCII character when the tool that produced the line wrote it
  and the line is recorded in a research note. Captured output is not ours to
  clean, and altering it would be the worse breach. The exception is enforced by
  `Characters.AllowInCapturedListings` in check-chapter.psd1, which requires
  both halves and forgives no control character, so it cannot reach prose or an
  invented listing. It covers punctuation a tool emitted; it is not a licence to
  paste a curly quote into a listing. See decision 60.
- Prefer a figure wherever a figure carries the point better than prose does.
  One diagram replaces three paragraphs describing an architecture; one plotted
  series replaces a four-row table. A figure is not decoration. It is a second
  tool of derivation, standing beside the code, the layers in the code, and the
  path a query or a request takes through them, rather than illustrating any of
  those after the fact. If a reader would have to hold four moving parts in
  their head to follow a paragraph, draw the four parts instead.
- TikZ figures follow the idiom the existing ones already use: hand-placed
  absolute coordinates rather than a layout engine, `-{Stealth[length=2mm]}`
  arrowheads, `rounded corners=2pt`, node dimensions in mm, and `font=\small`
  with `\scriptsize` for labels. A figure drawn to a different idiom reads as a
  figure borrowed from another book, which is why the existing pictures rather
  than this paragraph are the authority.
- The "Your turn" lab opens with a paragraph of framing, then a numbered list
  whose items begin with a bolded imperative (`\item \textbf{Map the
  owners.}`), and closes by saying what a dull result would mean or by pointing
  forward to the chapter that picks the thread up.
- mosaic-graph is laid out one folder per domain, and every field lives in the
  folder of the domain that owns it, even when it hangs off a type another
  domain declared. `Product` is a Catalog record, but `Product.price` is a
  resolver in `Pricing/Types/`. That is what makes chapter 08's extraction a
  move rather than a rewrite, so it holds even where a shortcut is tempting.
  Dependencies between domains stay acyclic and one-directional: the domain
  that references nobody is the one that can be extracted first.
- Do not enable `EmitCompilerGeneratedFiles` with an output path inside the
  project directory. The SDK compiles the emitted files as sources on the next
  build and the run fails with duplicate definitions. Dump them outside the
  project, or delete them once they have been read.

## Open items

An unresolved question, and the condition that unblocks it. Nothing else belongs
here, and decision 81 says where the rest goes: work owed to a chapter that is
not written yet sits in that chapter's Progress row, a lesson sits in the
writing rules above, and an answered question is deleted, because git holds the
history and the decision log holds the reason.

- **The composer crashes rather than erroring on one modelling mistake.** An
  entity interface whose interface carries `@key` and one of whose
  implementations does not makes `@wundergraph/composition` 0.63.2 throw out of
  `handleEntityInterfaces`, with a stack trace and a "please open an issue" box.
  It is committed as a case in `scripts/modeling-cases.mjs`, asserted by the
  crash message. Unblocked by reporting it upstream, which nobody has done, or
  by a release that turns it into a proper error, which fails the gate rather
  than making chapter 13 quietly wrong.
- **The composer input's subscription block is documented under a key the code
  does not read.** wgc 0.129.7 documents `websocket_subprotocol` and reads
  `websocketSubprotocol`, and `router compose` calls neither of the validators
  every other wgc command calls, so a wrong key and a wrong value are both
  silent. Committed as four cases in `scripts/realtime-cases.mjs`, asserted on
  the composed config. Unblocked by a wgc release that fixes either half, which
  fails the gate rather than making chapter 14 quietly wrong.
- **Turning on WebSocket authentication closes the graph to anonymous HTTP.**
  With `websocket.authentication.from_initial_payload` enabled, Cosmo Router
  0.337.1 answers `401 unauthorized` to every anonymous HTTP request, on a
  router whose `require_authentication` is false. Isolated by adding and
  removing that block and nothing else, and committed as a case in
  `scripts/router-cases.mjs`. Unblocked by reporting it upstream, which nobody
  has done, or by a release that fixes it, which fails the gate rather than
  making chapter 15 quietly wrong.
- **The router does not apply an initial-payload identity to its own field
  authorization**, and this one cannot be put in a gate yet. Measured while the
  block above was on: the router validated the token, exported it to Accounts
  correctly, and still refused an `@authenticated` field inside a subscription
  payload as `not authenticated`, on every event, with a token valid for an
  hour; a control with pre-fetch authorization off behaved identically.
  Reproducing it needs the configuration that 401s every anonymous request, and
  a gate that requires a broken graph is not a gate. Unblocked by the item
  above being fixed, at which point this becomes assertable and should be
  asserted.
- **`--split-configs-enabled` is the one wgc flag nothing has exercised.**
  Chapters 09 to 12 answered the rest between them. Unblocked by a chapter with
  a reason to split a config, most likely 21 or 22.
- **`samples/federated-wire` composes from committed schema files**, so changing
  a subgraph's C# and recomposing changes nothing, and the chapter 07 lab has to
  tell the reader to switch `graph.yaml` to `introspection:` before two of its
  exercises. Unblocked by that sample growing: at that point introspection
  becomes the committed default and the schema files stay only for the drift
  check.
