\section{The Wrong First Row}
\label{sec:ch13-wrong-first-row}

\index{pagination!ordering by a remote field|(}%
The graph has had sessions, scores and a paged \code{sessions} connection
since chapter~\ref{ch:second-third-subgraph}, and the first thing a conference
site wants from that combination is the best-rated talk. Ask for it the
obvious way:

\begin{minted}{graphql}
{
  sessions(first: 1) {
    nodes {
      title
      averageScore
    }
  }
}
\end{minted}

\index{pagination!the first row is the schedule's, not the ranking's}%
What comes back is the first session on the schedule, with its score attached:

\begin{minted}{json}
{
  "data": {
    "sessions": {
      "nodes": [
        {
          "title": "Schemas That Outlive Their Authors",
          "averageScore": 4
        }
      ]
    }
  }
}
\end{minted}

The highest average in this graph is 4.5, on \emph{Reading a Query Plan}, and
it is not in that response. Nothing answered wrongly. \code{sessions} sorts by
start time, as it has since chapter~\ref{ch:hot-chocolate-zero}, and adding
\code{averageScore} to the selection changed which columns came back and
nothing about what \code{first: 1} means.

\index{pagination!the argument that would need to exist}%
The request that would answer the question does not exist in this schema. It
would take a minimum score and a rating-descending order, and apply both
before it counted to one. Giving \code{sessions} those two arguments is a
morning's schema work and would not help, because the service behind the
field has start times and no ratings, and the service with the ratings has no
way to list sessions at all: it holds a row per score, and the session nobody
has rated is in no row it has. Each service can page what it stores. Neither
can page the thing the client asked about.

\index{pagination!is not the N+1}%
This is not chapter~\ref{ch:router-n-plus-1}'s problem wearing a different
field. Batching decides how many trips fetch the scores for a page that
already exists. It has nothing to say about which rows are on the page,
because that was settled before any score was fetched.
\index{pagination!ordering by a remote field|)}%
