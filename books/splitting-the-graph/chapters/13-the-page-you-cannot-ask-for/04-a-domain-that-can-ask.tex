\index{search document!what it carries}%
The document is one row per session, carrying everything a page decision
needs: when the session starts, its average, and how many scores went into
that average. The integer key stays out of the schema behind
\code{[GraphQLIgnore]}, as chapter~\ref{ch:hot-chocolate-zero} taught, because
a client is going to be handed a \code{Session} entity rather than a number.
I have left the doc comments off the records in this service, which is why
the schema it exports carries no descriptions where every earlier service's
does; the graph in front of you is a demonstration, and yours is not.

\begin{minted}{csharp}
namespace Search;

public sealed record SessionSearchDocument(
    [property: GraphQLIgnore] int SessionId,
    DateTimeOffset StartsAt,
    double? AverageScore,
    int RatingCount);
\end{minted}

\index{search document!complete before current}%
The seed is deliberately complete. Session~4 has no ratings and still has a
document, with a null average and a count of zero, which is the row a
projection grouped out of the ratings table alone could never produce.

\begin{minted}{csharp}
namespace Search;

public static class SessionSearchData
{
    public static readonly
        IReadOnlyList<SessionSearchDocument> Documents =
    [
        new(1, At(9), 4.0, 3),
        new(2, At(10), 4.5, 2),
        new(3, At(11), 3.0, 1),
        new(4, At(14), null, 0)
    ];

    private static DateTimeOffset At(int hour) =>
        new(2026, 9, 14, hour, 0, 0, TimeSpan.Zero);
}
\end{minted}

\index{ordering!the tie-breaker}%
\code{SessionId} is the primary key and, in the resolver below, the last
ordering key as well, so two equal start times or two equal scores still come
out in one fixed order. What that does not promise is a snapshot: a row can
still change between one page and the next.

\begin{minted}{csharp}
using Microsoft.EntityFrameworkCore;

namespace Search;

public sealed class SearchContext(
    DbContextOptions<SearchContext> options) : DbContext(options)
{
    public DbSet<SessionSearchDocument> SessionSearch =>
        Set<SessionSearchDocument>();

    protected override void OnModelCreating(ModelBuilder model)
    {
        model.Entity<SessionSearchDocument>()
            .HasKey(s => s.SessionId);
        model.Entity<SessionSearchDocument>()
            .Property(s => s.StartsAt)
            .HasConversion(
                v => v.UtcDateTime,
                v => new DateTimeOffset(v, TimeSpan.Zero));
        model.Entity<SessionSearchDocument>()
            .HasData(SessionSearchData.Documents);
    }
}
\end{minted}

One enum is enough for the two orderings this example needs:

\begin{minted}{csharp}
namespace Search;

public enum SessionSearchOrder
{
    StartsAt,
    RatingDescending
}
\end{minted}

\index{AsNoTracking@\code{AsNoTracking}}%
The resolver does everything that matters inside one \code{IQueryable}, and
the order of the calls is the point: the filter and the sort are on the query
before \code{[UsePaging]} adds its slice, which is the same rule
chapter~\ref{ch:data-without-n-plus-1} found for the projection.
\code{AsNoTracking} is new in this book and is EF Core's way of being told
that these rows will only ever be read, so it need not remember them for a
later save. Both orderings end with \code{SessionId}.

\begin{minted}{csharp}
using Microsoft.EntityFrameworkCore;

namespace Search;

[QueryType]
public static class Query
{
    [UsePaging(DefaultPageSize = 2, MaxPageSize = 10)]
    public static IQueryable<SessionSearchDocument> SearchSessions(
        SearchContext db,
        double? minimumScore,
        SessionSearchOrder? order)
    {
        var query = db.SessionSearch.AsNoTracking();
        if (minimumScore is not null)
        {
            query = query.Where(
                s => s.AverageScore >= minimumScore.Value);
        }
        return order is SessionSearchOrder.RatingDescending
            ? query.OrderByDescending(s => s.AverageScore)
                .ThenBy(s => s.SessionId)
            : query.OrderBy(s => s.StartsAt)
                .ThenBy(s => s.SessionId);
    }
}
\end{minted}

Notice what is absent. No call to Sessions, none to Ratings, none to the
router: Search decides the page alone, because everything the decision needs
is in its own table. That is the whole price of the projection, and the whole
point of it.
