## HC14 compatibility scope and minimal API deltas

The ch17-hc14 tag carries one Sessions service, not a port of the final four
services. Its Speakers rows and DataLoader remain inside Sessions. Do not
describe the absence of later services as an HC14 API limitation.

The measured API changes visible in the compatibility source are:

- Project target `net8.0`, all HC packages `14.3.1`, EF SQLite `9.0.19`.
- `Program.cs` uses `GraphQLServerOptions` and
  `GraphQLToolServeMode.Embedded` in `.WithOptions(...)`; there is no
  `using ChilliCream.Nitro.App;`.
- Remove the `QueryContext<T>` parameters and `.With(query)` from the
  IQueryable resolvers. The compatibility source materializes full rows.
- In `ShareNodeFields.cs`, use the `Definitions` namespace,
  `DefinitionBase`, `ObjectTypeDefinition` and `DirectiveDefinition` in place
  of the four corresponding HC16 `Configurations` names.
- `SpeakerType` is `ObjectType<Speaker>` with descriptor calls to
  `.Key("id")`, `.ResolveReferenceWith(...)`, `.ImplementsNode()` and
  `.ResolveNodeWith(...)`. This replaces the generated type-class attributes
  whose federation configuration HC14 does not apply in this source shape.
- The HC14 reference resolver obtains the schema's serializer through
  `context.Schema.Services.GetRequiredService<INodeIdSerializerAccessor>()`
  and `.Serializer`; it decodes the id and checks its type name before loading.
- HC14 has no `--semantic-non-null` schema-export flag. The unchanged verifier
  runs the command and checks the refusal rather than inferring it from docs.

The complete compatibility examples are readable via
`git show refs/tags/ch17-hc14:src/Sessions/<file>` without changing checkout.
